# Tovant

A trust-first marketplace connecting car owners with verified independent mechanics, mobile technicians, and detailers. Pilot market: Minneapolis–St. Paul, MN.

This is the v2 ground-up rewrite. See [`CLAUDE.md`](CLAUDE.md) for the full set of locked product/security decisions and design tokens.

## Stack

Next.js (App Router) + TypeScript + Tailwind v4, PostgreSQL + Drizzle ORM, better-auth (email/password + mandatory TOTP 2FA), Stripe (Billing + Connect Express + Identity), Checkr, Postmark + Twilio, S3-compatible object storage. Third-party integrations run in stub mode by default (see `src/lib/integrations/`) until real credentials are provided — set the relevant `*_MODE=live` in `.env` once you have them.

## Setup

1. `pnpm install`
2. Copy `.env.example` to `.env`:
   - `DATABASE_URL` — a free [Neon](https://neon.tech) Postgres project works well for local dev.
   - `BETTER_AUTH_SECRET` — generate with `node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"`.
   - Everything else can stay blank; integrations default to stub mode.
3. `pnpm db:migrate` — applies the committed migrations in `drizzle/` to your database.
4. `pnpm dev` — starts the app at http://localhost:3000.

## Scripts

- `pnpm dev` — start the dev server
- `pnpm build` / `pnpm start` — production build/run
- `pnpm lint` / `pnpm typecheck` — ESLint / TypeScript checks
- `pnpm test` — Vitest unit/integration tests
- `pnpm test:e2e` — Playwright end-to-end tests (starts its own dev server; needs a real `DATABASE_URL`)
- `pnpm db:generate` — generate a new migration from schema changes in `src/db/schema/`
- `pnpm db:migrate` — apply committed migrations
- `pnpm db:push` — push schema directly without a migration file (prototyping only)
- `pnpm db:studio` — open Drizzle Studio against the configured database

## Project layout

- `src/app/` — routes, split into `(auth)` (login/signup/2FA) and role-gated trees `owner/`, `provider/`, `admin/` (real path segments, not route groups — two same-named pages in different route groups would collide on the same URL, so each role gets its own prefix).
- `src/db/schema/` — Drizzle table definitions. `auth.ts` is generated by the better-auth CLI (`pnpm dlx @better-auth/cli generate --config src/lib/auth/auth.ts --output src/db/schema/auth.ts`) — don't hand-edit it; change `src/lib/auth/auth.ts` and regenerate instead.
- `src/lib/auth/` — better-auth server/client config and the `requireRole()` guard used by each role tree's layout.
- `src/lib/security/` — the shared row-level ownership check (`ownership.ts`) and append-only audit log writer (`audit-log.ts`) required by every quote/job/payment/dispute/message route.
- `src/lib/integrations/` — one interface per third-party dependency (`types.ts`), a stub + live implementation per service, and `registry.ts` as the single env-driven swap point. Always import from the registry, never from a `*.stub.ts`/`*.live.ts` file directly.
